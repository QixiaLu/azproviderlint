# AZR001

The AZR001 analyzer reports `SetId` being called with a dereferenced pointer, typically the
raw Resource ID returned by the Azure API (`d.SetId(*read.ID)`).

The Azure API returns Resource IDs inconsistently (casing and segment order can differ
between services and operations), so Terraform manages its own Resource IDs. New resources
should build the ID with a generated Resource ID Formatter and call `d.SetId(id.ID())`.

A Resource ID Formatter, Parser and Validator can be generated by adding a `resourceids.go`
file to the service package containing:

```go
//go:generate go run ../../tools/generator-resource-id/main.go -path=./ -name=Server -id={the value of the Resource ID}
```

and running `make generate`.

## Flagged Code

```go
d.SetId(*read.ID)
```

## Passing Code

```go
subscriptionId := meta.(*clients.Client).Account.SubscriptionId
id := parse.NewServerID(subscriptionId, resourceGroup, name)
d.SetId(id.ID())
```

When parsing the Resource ID during Read, Update or Delete, use the generated parser:

```go
id, err := parse.ServerID(d.Id())
if err != nil {
	return err
}
```

## Ignoring Reports

When run via golangci-lint, reports can be ignored with a `//nolint:azproviderlint` Go code
comment at the end of the offending line or on the line immediately preceding it:

```go
d.SetId(*read.ID) //nolint:azproviderlint
```
